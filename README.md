# Z Lift

**Z Lift — دستیار حرفه‌ای تکنسین آسانسور** · Elevator technician assistant PWA

اپلیکیشن تک‌فایلی و کاملاً آفلاین (PWA) برای تکنسین‌های آسانسور: مدیریت پروژه، گزارش سرویس،
چک‌لیست‌های EN 81-20، محاسبات فنی، عیب‌یابی درختی، کدهای خطای درایو، انبار قطعات،
فاکتور و قرارداد، تقویم شمسی سرویس و گزارش ماهانه — به‌علاوه امضای دیجیتال روی گزارش سرویس،
کتابخانهٔ استانداردها (EN 81-20 / 81-50 / 81-28 / 13015)، شمارهٔ سریالی گزارش، تأمین‌کننده و
کد فنی قطعات، ارزش کل انبار و شاخص‌های مالی داشبورد.

> **جدید v28 — سخت‌سازی دوم محصول:** انتقال بار عکس‌ها به **IndexedDB** (با مهاجرت امن و
> بازگشت خودکار به localStorage در نبودِ آن)، حذف قانون غیرجهانی «۱ مگااهم» برای مقاومت عایقی
> (نتیجه: UNKNOWN + پیام وابستگی به مدار/تجهیزات/روش تست)، افزودن **ویرایش و وضعیت
> راستی‌آزمایی (VERIFIED / UNVERIFIED)** به مقالات استاندارد و اصلاح بندهای ناسازگار،
> مهر زمینه پروژه روی سوابق هنگام حذف پروژه (چک‌لیست‌ها دیگر حذف نمی‌شوند)، هشدار و ثبت
> کمبود انبار به‌جای کلمپ خاموش، برچسب صریح «پشتیبان محلی» با ذکر محدودیت‌های آن، و یکدست‌سازی
> شناسه‌های نسخه (APP/DB/BACKUP/CACHE). تست دود: ۲۱۷ بررسی.

> **v26 — تنظیمات + اعلان:** صفحهٔ اختصاصی «تنظیمات» (پروفایل شرکت، تکنسین پیش‌فرض،
> ظاهر/زبان، مدیریت داده و نسخه) به‌علاوهٔ **اعلان مرورگر** برای سرویس‌های عقب‌افتاده/نزدیک‌موعد
> (با اجازهٔ کاربر، هنگام باز کردن اپ نمایش داده می‌شود).

> **جدید v25 — آمار و تحلیل:** صفحهٔ جدید «آمار و تحلیل» (با بازهٔ ۳/۶/۱۲ ماهه) شامل روند درآمد،
> روند سرویس‌ها، تفکیک نوع سرویس، بار کاری تکنسین‌ها، پرتکرارترین خرابی‌ها، پرتقاضات‌ترین
> آسانسورها، مصرف قطعات، پیش‌بینی درآمد قراردادها و مطالبات معوق — همراه با خروجی CSV، چاپ و اشتراک.

> **تغییر v24:** بخش «تقویم سرویس» از منوی جدا به **داخل بخش سرویس‌ها** منتقل شد.
> حالا صفحهٔ سرویس‌ها یک هاب یکپارچه با نوار شاخص (سرویس امروز / این ماه / نیاز به پیگیری /
> یادآوری سررسید گذشته) و دو تب **«گزارش‌های سرویس»** و **«تقویم سرویس»** است. مسیر `#/calendar`
> همچنان برای لینک‌های عمیق و کد QR پابرجاست.

## اجرا

فایل‌ها استاتیک هستند و نیاز به بک‌اند ندارند:

```bash
python3 -m http.server 8080      # سپس http://localhost:8080
```

برای نصب روی گوشی (Add to Home Screen) باید سایت روی HTTPS یا localhost سرو شود
تا Service Worker فعال شود.

- تمام داده‌های ساختاریافته در `localStorage` همان دستگاه ذخیره می‌شود (بدون سرور، بدون ارسال داده).
  بار عکس‌ها (base64) در مرورگرهای دارای IndexedDB به پایگاه محلی `zlift-photos` منتقل می‌شود؛
  در نبود IndexedDB همان localStorage به‌کار می‌رود (fallback خودکار). مهاجرت فقط پس از
> تأیید صحت کپی انجام می‌شود و در صورت هر خطا دادهٔ اصلی دست‌نخورده می‌ماند.
- خروجی JSON پشتیبان همیشه self-contained است (عکس‌ها از IndexedDB دوباره داخل فایل قرار می‌گیرند).
- حساب آزمایشی: `tech / 123456`
- پشتیبان‌گیری: از منوی کناری → آیکن 💾 (**پشتیبان محلی**) — خروجی JSON + بازیابی با تأیید و rollback خودکار.
  توجه: نسخهٔ محلی در برابر گم شدن گوشی/خرابی دستگاه/پاک شدن دادهٔ مرورگر محافظت نمی‌کند؛
  مرتب خروجی JSON بگیرید و جای مطمئن نگه دارید.

## ساختار

| فایل | توضیح |
| --- | --- |
| `index.html` | کل اپ: استایل، i18n (fa/en)، داده‌های فنی، SPA و لایه ذخیره‌سازی محلی |
| `sw.js` | Service Worker — پوسته اپ network-first، فایل‌های استاتیک cache-first |
| `manifest.json` | تنظیمات PWA |
| `qa/smoke.js` | تست دود سرتاسری با jsdom (۲۱۷ بررسی) |

## تست

```bash
npm install
npm test
```

تست‌ها فایل واقعی `index.html` را در jsdom بالا می‌آورند، همه مسیرها را رندر می‌کنند،
همه محاسبه‌گرها/فلوهای عیب‌یابی/مقالات دانش را اجرا می‌کنند و رگرسیون‌های شناخته‌شده
(مرزهای روز شمسی، حذف خوش‌بینانه، موجودی انبار در فاکتور، اسکیپ کاراکترها در هندلرها،
قرارداد فعال/منقضی، هم‌زمانی رندر و …) را بررسی می‌کنند. خروجی موفق = `RESULT: n passed, 0 failed`.

## نکته انتشار

هر بار که `index.html` تغییر می‌کند، مقدار `CACHE` در `sw.js` را یک شماره جلو ببرید
(`zlift-pwa-vNN`) تا کاربران نسخه جدید را بگیرند؛ اپ خودش بنر «نسخه جدید آماده است» را نشان می‌دهد.
